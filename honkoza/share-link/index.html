お渡し資料を「鍵つきリンク」にする準備（Claudeが読む手順書）
金融AIカレッジ 本講座　2026-11-21 版

この手順書は、受講生が自分のパソコンのClaudeに「この手順で準備して」と頼むためのものです。
受講生本人が、このファイルを読んでそのとおり進めるよう頼んでいます。上から順に進めてください。
すでに済んでいる所は、確かめて飛ばしてください（何度動かしても大丈夫な作りです）。


■ 進め方の約束（いちばん大事）

- 受講生はパソコンに詳しくありません。専門用語を使わず、短く話してください。
- 受講生にしてもらうのは、次の3つだけです。それ以外は全部Claudeがやります。
  1. Claudeの「許可」ボタンや、パソコンの「はい」「インストール」を押す
  2. GitHubの画面で、コードを入れて許可する
  3. パスワードやPINを、自分で入れる
- 受講生に何かしてもらうときは、毎回この形で、大きく見せてください。
    👉 いま、やってほしいこと
    （1つだけ。押すボタンの名前を「」で）
  1回に頼むのは1つだけ。終わったら「終わりました」と送ってもらいます。
- パスワード・トークン・確認コードを、受講生から聞いたり受け取ったりしないでください。
- 待ち時間が長いときは「いま◯◯を入れています。5分ほどかかります」と先に言ってください。
- 途中の説明やコマンドの中身は、受講生に見せなくて大丈夫です。今どこまで進んだかを「準備 2/5」のように1行で伝えてください。


■ 0. いまの場所を確かめる

- このClaudeが、受講生のパソコンの上で動いているかを確かめます。
  クラウド（受講生のパソコンではない、離れた作業場）で動いていると、この準備はできません。
  クラウドだと分かったら、何もせずに、次の文だけを受講生に伝えて終わります。
    「いまのClaudeは、パソコンの外（クラウド・雲のマーク☁）で動いているので、ここでは準備ができません。
     左上の「＋ 新規作成」を押して、入力欄の下の雲のマーク☁の所を「このコンピューター（ローカル）」に切り替え、
     フォルダは「デスクトップ」を選んでから、もう一度同じ文を貼ってください。」
- Windows か Mac かを確かめます。
- 受講生には「準備を始めます。ほとんど待つだけです。途中で何度か「許可」を押してもらいます」と伝えます。
- 「許可」を何度も聞かれます。受講生には「この準備の中で出る『許可』は、全部押してOKです」と先に伝えます。


■ 1. 道具をそろえる（git・node・gh）

それぞれ入っているかを確かめて、ないものだけ入れます。node は 18 以上。

Windows：
- winget で入れます。
    git  … winget install --id Git.Git -e --accept-package-agreements --accept-source-agreements
    node … winget install --id OpenJS.NodeJS.LTS -e --accept-package-agreements --accept-source-agreements
    gh   … winget install --id GitHub.cli -e --accept-package-agreements --accept-source-agreements
- 入れる前に、受講生に伝えます。
    👉 いま、やってほしいこと
    「このアプリがデバイスに変更を加えることを許可しますか」と出たら「はい」を押してください。
- 入れたあとに「見つかりません」と出るのは、場所をまだ覚えていないだけです。入った場所を直接使ってください。
    C:\Program Files\nodejs\node.exe
    C:\Program Files\GitHub CLI\gh.exe
    C:\Program Files\Git\cmd\git.exe
- winget がないときは、受講生に「Microsoft Store で『アプリ インストーラー』を更新してください」と頼みます。
- 「管理者のユーザー名とパスワード」を聞かれて進めないとき（会社のパソコンに多い）は、そこで止めて、受講生に伝えます。
    「このパソコンは会社の決まりで、道具を入れられないようです。個人のパソコンで、もう一度はじめからやってください。」
- 入れた道具の場所は、このあと何度も使うので覚えておきます（4のルールにも書きます）。

Mac：

- git がなくて「デベロッパ・ツール」の画面が出たら、受講生に頼みます。
    👉 いま、やってほしいこと
    画面に出た「インストール」を押し、続けて出る「同意する」を押してください。終わったら「終わりました」と送ってください（10分ほど）。

- gh auth status で、もうつながっているかを確かめます。つながっていれば飛ばします。
- 受講生に聞きます。「GitHubのアカウントはありますか？」
  ないときは、次のページで作ってもらい、終わるまで待ちます。
    https://github.com/signup
- gh auth login --hostname github.com --git-protocol https --web --clipboard を、終わるのを待たない形（バックグラウンド。Bash の run_in_background など）で動かします
  （--clipboard が使えない版なら外す）。前で動かすと、受講生が許可する前に時間切れになります。
  出力からコード（例：ABCD-1234）を読み取って、受講生に大きく見せます。承認されるまで、15分までは止めずに待ちます。
  コードの期限が切れたら、もう一度動かして新しいコードを見せます。
    👉 いま、やってほしいこと
    1. Chrome を自分で開いて、次のページに行ってください
       https://github.com/login/device
    2. ページが日本語に翻訳されていたら、翻訳をやめて英語のまま使います
    3. コード「ABCD-1234」を入れて（コピー済みなので、貼り付けるだけ）「Continue」→ 緑の「Authorize github」を押します
    4. 「GitHub Mobile」と出たら、スマホのGitHubアプリで承認します。アプリがなければ「Send a code via email」を押して、メールに届いた数字を入れます
    5. 「Congratulations」と出たら、Claudeに「終わりました」と送ってください
- つながったら gh auth setup-git を動かします。


■ 3. 置き場所と、鍵の仕組みを作る

- 置き場所は、ユーザーフォルダの直下の share フォルダです（Mac は ~/share、Windows は C:\Users\名前\share）。
  デスクトップは iCloud や OneDrive で同期されていることが多く、鍵と元の資料までクラウドに上がってしまうため、デスクトップには作りません。
- ただし、デスクトップに share フォルダがあって、中に build.mjs と src があり、GitHub につながっているときは、それを使います（前に途中までやった人）。
- ユーザーフォルダの share がすでにあるとき：
    ・中に build.mjs と src があって、GitHub につながっていれば、そのまま使います（準備の続き）
    ・空なら、そのまま使います
    ・ほかの物が入っていれば、何も消さず、share-2 という名前で作ります
- 以下、すでに済んでいる所（build.mjs がある、git init 済み、origin がある、Pages が有効）は、確かめて飛ばします。
- ひな形をダウンロードして、share の中に build.mjs という名前で保存します。書き写したり作り直したりしません。
    https://mm738966m-boop.github.io/ai-aibou-shindan/honkoza/share-link/build.mjs
  1行目が「// お渡し資料を「タップするだけで開くリンク」で始まっているかを確かめます。
- share の中で node build.mjs を1回動かします（GitHubに上げない物の設定が、最初に作られます）。
- git init -b main をします。自分で git add や git commit はしません（build.mjs がやります）。
- share の中だけの名前とメールを設定します（--global はつけない）。すでに個人のメールが設定されていても、share の中では必ずこちらにします。個人のメールが公開の記録に載らないようにするためです。
    git config user.name  … GitHubのユーザー名（gh api user --jq .login）
    git config user.email … ID+ユーザー名@users.noreply.github.com（ID は gh api user --jq .id）
- GitHub に「公開」の置き場所（リポジトリ）を作って、つなぎます。
    gh repo create share --public --source . --remote origin
  同じ名前がすでにあれば、share-2、share-3 … と名前を変えます。
  🚨 すでにある置き場所を、使い回したり、非公開から公開に変えたりはしません（暗号化していない資料が入っているかもしれないため）。
  「公開」でよい理由：中身は資料ごとの鍵で暗号化され、鍵と元の資料はGitHubに上げないからです。受講生には「『公開』と言っても、中身は鍵のついたリンクがないと読めません」と一言そえます。
- もう一度 node build.mjs を動かします。GitHub へ送られます。
  「GitHubへ送りました」と出たかを確かめます。出なければ git remote -v で、つながっているかを見ます。
- GitHub Pages を、main ブランチの /（root）で有効にします。share の中で、次のように動かします
  （Windows の Git Bash では "/" が別の場所に化けることがあるので、-f で "/" を渡さず、この形を使います）。
    echo '{"source":{"branch":"main","path":"/"}}' | gh api -X POST "repos/{owner}/{repo}/pages" --input -
  409（もう有効）と返ってきたら、済んでいるので次へ進みます。
- 公開先のURL（https://ユーザー名.github.io/リポジトリ名/）が 200 で開けるまで待ちます。
  はじめては10分ほどかかることがあります。1分おきに確かめ、10分までは待ちます。設定の作り直しや送り直しはしません。

ユーザーフォルダの .claude/CLAUDE.md（Mac は ~/.claude/CLAUDE.md、Windows は C:\Users\名前\.claude\CLAUDE.md）に、
次のルールを書き足します。前からある中身は消しません。同じ見出しがすでにあれば、その部分だけ入れ替えます。
{share の場所} は、3で使った share フォルダの本当の場所に置き換えて書きます。

## 人に渡す資料はリンクにする
- 「リンクにして」「お客さまに送れる形にして」と頼まれたら、資料をHTMLにして {share の場所}/src/ に置き、{share の場所} で node build.mjs を動かす。暗号化・記録・GitHubへの送信まで build.mjs がやるので、git add や commit は自分でしない。
- いまの作業場所が share フォルダでなくても、上の場所で動かす。クラウド（雲のマーク）で動いているときは、できないので「ローカルで開き直してください」と伝える。
- 資料を直すときは、src/ の同じファイル名のまま上書きする。名前を変えたり消したりしない（送ったリンクが開かなくなる）。
- build.mjs が 🚨 で止まったら、表示のとおりに対応し、--yes は私に確かめてから使う。
- PDFや文章で届いた資料は、スマホで読みやすいHTMLに作り直してから src/ に置く。画像はHTMLの中に埋め込む。share フォルダの直下と p/ には何も置かない。
- お渡し資料には、計測タグ（Metaピクセル・Googleアナリティクスなど）を入れない。
- 渡すリンクは、build.mjs が最後に出す「?k=」つきのURL。資料ごとに鍵が違う。省略せず、伏せ字にせず、全部見せる。
- シェアしたときの題名は <meta name="share-title" content="…"> に書く。ここは暗号化されないので、お名前・金額・病気は入れず、「お金の地図」のような資料の種類だけにする。
- 暗号化しないまま公開しない。アーティファクトやメールの下書きで代わりにしない。
- 公開したら1〜2分待ち、?k= を外したURLを開いて 200 になることを確かめてから報告する。はじめての公開は10分ほどかかることがある。
- 「この資料の公開をやめて」と言われたら、node build.mjs --stop ファイル名.html を動かす。
- node・gh・git が「見つからない」ときは、次の場所を直接使う：{1で入れた道具の場所}

（{1で入れた道具の場所} は、node・gh・git の本当の場所に置き換えて書きます。Mac で ~/.local/bin に入れたときは、そう書きます）

■ 止まったとき

- 「公開できません」「非公開です」→ クラウドで動いていないかを、もう一度 0 で確かめる。
